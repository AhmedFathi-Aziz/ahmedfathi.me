What Happens When You Type google.com into Your Browser?

A Journey Through Computer Networking, DNS, HTTPS, and Web Communication

By Ahmed Fathi

Introduction

What actually happens between pressing Enter and seeing Google's homepage appear on the screen?

To answer this question, we need to look beyond the browser. Imagine a computer connected to a local network through an Ethernet switch. The computer has an IP address, a default gateway, and a configured DNS resolver. Yet none of these details tells the browser what the Google homepage looks like.

The browser must first identify the destination server. The operating system then determines how to send traffic beyond the local network, while routers forward packets toward their destination. Once communication is established, the browser exchanges HTTP messages with Google's infrastructure and processes the returned content.

Each stage solves a different problem. By following one web request from the local network to the destination server, we can understand how switching, IP addressing, routing, DNS, and HTTPS work together.

1. Before Opening the Browser: Understanding the Local Network

Before a computer can communicate with a website on the Internet, it must first be connected to a properly configured network.

Consider a local area network (LAN) containing several computers connected through an Ethernet switch and a router that provides access to external networks.

Each device requires appropriate network configuration, including an IP address, subnet mask, and routing information. A DNS resolver is also needed to translate domain names into network addresses.

These settings may be assigned automatically through DHCP or configured manually.

1.1 The Role of a Network Switch

Imagine three computers connected to the same Ethernet switch. When PC1 sends data to PC2, how does the switch determine which port should receive the frame?

The answer lies in the switch's MAC address table. As frames arrive, the switch learns the source MAC addresses and associates them with the ports on which they were received. It then uses this information to forward subsequent frames toward their intended destinations.

In a conventional Ethernet network, a switch operates primarily at Layer 2 of the OSI model, commonly called the Data Link Layer.

Each Ethernet interface has a MAC address, which is used for communication across the local network.

When a switch receives an Ethernet frame, it examines the source MAC address and learns which port is associated with that address.

This behavior allows Ethernet switches to forward local traffic efficiently without sending every known unicast frame to every connected device.

However, a switch does not ordinarily determine how to reach remote Internet networks. That responsibility belongs to routing devices.

1.2 DHCP: How a Computer Obtains Network Configuration

When a computer joins a network, it usually requires several configuration parameters before it can communicate effectively.

These may include an IP address, subnet mask, default gateway, and DNS resolver addresses.

Manually configuring every device would be inconvenient, particularly in networks with many computers.

The Dynamic Host Configuration Protocol (DHCP) automates this process.

A common DHCP address-allocation exchange follows four steps, collectively known as DORA:

Discover: The client broadcasts a DHCPDISCOVER message to locate available DHCP servers.
Offer: A DHCP server responds with a DHCPOFFER containing proposed configuration information.
Request: The client sends a DHCPREQUEST to indicate the configuration it wishes to use.
Acknowledgment: The server sends a DHCPACK confirming the allocation.

DHCP can also assign a lease duration, defining how long the client may use the assigned configuration before renewal is required.

1.3 The Default Gateway and Communication Outside the LAN

Suppose a computer has the IP address 192.168.23.100 with a subnet mask of 255.255.255.0.

Its local IPv4 subnet is 192.168.23.0/24.

When a computer needs to communicate with another device, it first determines whether the destination IP address belongs to its local subnet. If the destination is within the same subnet, the computer can communicate with it directly through the local network. However, if the destination is outside the local subnet, the computer typically forwards the traffic to its default gateway, which is responsible for routing the packets toward the destination network.

However, Google servers are not normally part of the user's local subnet.

The computer therefore consults its routing table and typically forwards traffic toward its default gateway.

A default gateway is usually a router that provides connectivity to other networks.

For IPv4 communication over Ethernet, the computer may use Address Resolution Protocol (ARP) to discover the MAC address of the next-hop router.

The resulting Ethernet frame is delivered to the router, which processes the IP packet and forwards it toward the destination.

An important distinction is that IP addresses identify logical communication endpoints, while Ethernet MAC addresses support delivery across an individual local network link.

2. DNS: How the Browser Finds google.com

After the computer has network connectivity, the user opens a browser and enters google.com.

The browser recognizes the text as a domain name and prepares to access the corresponding web service.

However, Internet routing does not operate directly on human-readable domain names.

To communicate with a remote server, the computer generally needs an IP address associated with the requested hostname.

The Domain Name System (DNS) provides the distributed naming infrastructure used for this purpose.
