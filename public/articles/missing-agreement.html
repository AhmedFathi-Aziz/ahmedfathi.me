A File Went Missing. What Can the Evidence Actually Prove?

By Ahmed Fathi

Minutes before a meeting, a contracts manager opens the Contracts folder on the team's USB drive. The signed agreement he needs is missing. He remembers seeing Omar sitting at the office computer earlier that afternoon. "Do you think Omar deleted it?" he asks.

I ask the manager for the filename. He gives me Signed-Agreement-104.docx. When was the agreement last seen, and what did Windows record against that exact name?

I would start by finding the last time anyone could still see the agreement. That would narrow the search to a few minutes of activity on the shared computer. The Windows log could tell me which account accessed the document during that interval. The USB drive could answer the manager’s other question: could he get his signed copy back?

Identifying the missing agreement

I recreated this scenario on a Windows 11 computer with two local accounts and a USB drive. The screenshots show what Windows recorded during the exercise.

What did Omar access?

The manager had seen Omar at the shared computer earlier that afternoon. I opened Event Viewer on that computer and filtered the Windows Security log for event 4663. At 15:05:18 on 18 November 2026, I found an entry under Omar's account.

Reading past the account name

I checked the Object Name field to see what Omar had accessed. The path ended at the Contracts folder. Under Accesses, Windows showed ReadData (or ListDirectory). For a folder, that means listing its contents. The Process Name field identified PowerShell.

Was the agreement still there after Omar’s visit?

At 15:53:06, nearly 48 minutes after Omar listed the folder, a PowerShell check returned the agreement's full path and its size of 13,446 bytes. The document was still on the drive after the recorded folder visit.

The entry that named the agreement

At 15:57:30, another 4663 entry contained a longer path. This one ended in Signed-Agreement-104.docx. I read the access field before checking the account name.

Under Subject, Windows identified the account as Fathi\Maya.

What can we tell the manager?

By 15:58:25, a check of the same path returned False. The agreement had disappeared from the location where the manager expected to find it.

“The agreement was still on the drive at 15:53, nearly 48 minutes after Omar's account listed the folder,” I told the manager. “At 15:57:30, Windows recorded delete access to the agreement under Maya's account. I'd speak to Maya next to establish who was using that session.”

The manager still needed the signed agreement for his meeting. Could we recover it from the USB drive?

Recovering the signed agreement

When a file is deleted, the file system can mark its space as available while some or all its contents remain on the drive. Further writes may reuse that space. My first question in FTK Imager was whether the Contracts folder still contained a deleted entry for the agreement. Finding its name would give me a candidate to extract. I would then need to check what had survived.

I opened the SanDisk USB drive in FTK Imager and browsed to the Contracts folder. Two deleted entries had the name I was looking for. One was empty. The other was 13,446 bytes, exactly the size recorded when the agreement was still present.

I selected the 13,446-byte entry and exported it. FTK Imager reported that it had copied all 13,446 bytes.

Was it the same signed copy?

Two documents can have the same name and size even if a single digit in the contract has changed. SHA-256 calculates a fingerprint from the file’s contents, so that change would produce a different value. I had recorded the original fingerprint while the agreement was still on the drive. Now I could calculate the fingerprint of the exported file and compare the two.

The fingerprints matched. I could give the manager his signed agreement back and show him how I knew it was the same file.

Technical reference: Microsoft Learn, Event 4663
